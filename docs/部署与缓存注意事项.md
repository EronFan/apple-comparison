# 部署与缓存注意事项

## Cloudflare 对 /public 静态文件的长缓存（2026-09-12）

**现象**：Cloudflare 对 `/public` 下的静态文件（如 `/public/js/languages.js`）按自有规则强制长期缓存（`cache-control: public, max-age=31536000, immutable`），**覆盖了 vercel.json 里 `max-age=0, must-revalidate` 的配置**。部署新版本后，该 URL 仍会返回旧的缓存文件。

**后果**：只要修改了 `public/js` 下的文件（如 languages.js 加词条、theme.js 改样式），线上用户会继续加载旧 JS，页面表现为"代码已上线但功能/文案不生效"。2026-09-12 电池天梯图系列按钮空白即因此导致：页面 HTML 是新的，但旧 languages.js 里没有新增词条。

**正确做法**：改动 `public/js` 下任何文件后，**必须同步更新所有页面里引用该文件的 `?v=` 版本号**（如 `languages.js?v=20260912` → `?v=新日期`）。版本号变了 URL 就变了，CDN 和浏览器旧缓存自然失效。

- 涉及文件：各页面引用的 `languages.js`、`language-switcher.js`、`theme.js`（2026-09-12 已统一加 `?v=20260912`）。
- 快速批量更新：`perl -pi -e 's|(js/languages\.js)\?v=\d+|$1?v=新日期|g' src/*.html`（其余两个文件同理）。
- HTML 页面本身（/src/*.html）是 `must-revalidate` 的，不受此问题影响，无需加版本号。
- 数据 JSON（如 iphone_refined.json）页面已用 `Date.now()` 动态参数请求，也不受影响。

**彻底方案**（未实施）：在 Cloudflare 后台为 `/public/js/*` 添加"绕过缓存 / 遵循源站缓存头"规则，之后可去掉版本号机制。
